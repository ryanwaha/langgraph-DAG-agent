# NexCortex-04：三通道完備性推導與語意類型映射

> 本文件補充項目啟動說明（§2 元原則）與（§13 ETL Pipeline）之間缺失的推導環節。
> 從文本的語意構成出發，自下而上論證三通道分割為何是完備的。
> 推導動機：自上而下的架構設計（元原則 → 設計原則）與自下而上的文本分析（語意類型 → 可壓縮性）各自獨立收斂至相同結論，但此收斂性在既有文件中從未被顯化。本文件修補此論述缺口。

---

## §1 問題陳述

項目啟動說明確立了元原則：

> 存儲層只合法存放脈絡無關的結構性事實與最低限度的信號標記。

並定義了三個檢索通道：

| 通道 | 存儲系統 | 捕捉的面向 |
|------|----------|------------|
| 圖通道 | Kuzu (GraphDB) | 概念共現的拓撲骨架 |
| 向量通道 | 向量索引 | 全文語意的粗粒度相似度 |
| 時序-認識論通道 | Event Log + 敘事層 (LCM DAG) | 認知漂變的時序結構與認識論事件 |

未回答的問題：**為什麼這三個通道足以覆蓋文本中所有有意義的語意？是否存在第四種語意面向，不被任何通道捕捉？**

---

## §2 文本的五種語意類型

從可壓縮性（而非內容）的角度分析，任何 Q-A 對話節點中的文本可窮舉為五種語意類型：

| # | 語意類型 | 定義 | 可壓縮性 |
|---|----------|------|----------|
| 1 | 命題（Proposition） | 原子性的事實聲明或判斷 | 幾乎不可壓縮——刪除即丟失 |
| 2 | 推理鏈（Reasoning Chain） | 從前提到結論的推導步驟 | 雙態：可從已知前提推導者高度可壓縮；包含新穎推理者不可壓縮 |
| 3 | 結論/決策（Conclusion/Decision） | 推理的終點或明確的行動選擇 | 不可壓縮，但天然短小 |
| 4 | 脈絡/動機（Context/Motivation） | 為什麼討論這個話題、背景是什麼 | 高度可壓縮（可濃縮至一句） |
| 5 | 元對話（Meta-discourse） | 對話管理、禮貌用語、重複確認 | 100% 可壓縮（零語意載荷） |

**窮舉性論證**：任何文本片段要麼在做聲明（1）、在做推導（2）、在給結論（3）、在交代背景（4）、或在管理對話本身（5）。這五類覆蓋了所有命題性內容（1-3）、所有脈絡性內容（4）、與所有非語意性內容（5）。

## §3 五種語意類型在三通道中的映射

### 映射表

| 語意類型 | 圖通道（共現拓撲） | 向量通道（語意相似度） | 時序-認識論通道 | 完整性 |
|----------|-------------------|----------------------|----------------|--------|
| 命題 | 概念標籤 → 共現邊 | sum 全文嵌入 | — | 完整：圖提供座標，向量提供內容 |
| 推理鏈 | 各步驟涉及的概念 → 共現邊 | sum 中保留的推理文本 | 敘事層保留跨 session 推理脈絡 | 完整：方向性由 LLM 在查詢時從文本重建 |
| 結論/決策 | 結論涉及的概念 → 共現邊 | sum 全文嵌入 | structural_change 維度可能觸發 | 完整 |
| 脈絡/動機 | 弱（動機未必產出概念標籤） | sum 壓縮後的殘留 | 敘事層 Level 0 保留原始動機 | 完整：sum 壓縮的損失由敘事層補回 |
| 元對話 | — | — | — | 完整：設計性丟棄，零語意載荷 |

### 關鍵觀察

1. **無第四通道的必要性**：五種語意類型中，每一種都至少被一個通道覆蓋。元對話被設計性丟棄（合法）。其餘四種均有明確歸宿。

2. **向量通道是安全網**：除元對話外，所有語意類型的原始文本均透過 sum 進入向量索引。即使圖通道遺漏了某個概念，向量通道仍保留其語意。向量的失敗模式是 false positive（多召回），不是 false negative（漏召回）——對 RAG 而言安全。

3. **推理鏈的方向性**：共現是對稱的，推理是有向的。圖通道無法區分「A 導致 B」與「B 導致 A」。這不是缺陷——方向性是脈絡相關的語意判斷，依元原則不應在存儲層固化。LLM 在查詢時從 sum 文本（向量通道召回）重建方向性。

4. **脈絡/動機的雙重保障**：sum 壓縮將動機濃縮至一句（高度壓縮），細節丟失。但敘事層 Level 0（日粒度）保留了動機的完整表述。這是敘事層存在的核心理由之一——承接 sum 壓縮中刻意丟棄的脈絡維度。

## §4 完備性的前提條件

三通道完備性成立，但依賴以下前提。這些前提是參數性的（可透過 POC 迭代校準），不是結構性的（不需要重新設計架構）。

### 前提 P0：sum 壓縮的保真度

sum 是所有下游處理的唯一輸入。若 sum 丟失某種語意類型，無下游通道能恢復。

- 五種語意類型中，命題（1）和新穎推理鏈（2b）是不可壓縮的——sum 必須完整保留
- 結論（3）天然短小，壓縮風險低
- 脈絡（4）可壓縮，且有敘事層備份
- 元對話（5）合法丟棄

**校準方式**：Stage 0（sum 壓縮 pipeline）的品質驗證。

### 前提 P1：概念抽取的非系統性偏斜

若 LLM 系統性地遺漏某類概念（如過程性概念：「重構」「遷移」「辯證」），圖拓撲會缺少一整個維度。向量通道不受影響，但圖通道可能退化為噪音。

**校準方式**：POC Stage 2 的概念抽取評估（E1-E4）。

### 前提 P2：session 邊界的主題收斂性

共現定義為「同一 session 出現 = 共現一次」。若 session 主題鬆散（漫談），session 內的兩兩共現產生大量虛假邊，Louvain 社群結構失真。

**校準方式**：POC Stage 5 的模組度 Q 值與人工評估。

### 前提 P3：Agent 的多通道組合策略

三通道的互補性要求 Agent 能在查詢時可靠地從多通道收集碎片。若 Agent 策略只命中單一通道，LLM 缺乏足夠素材重建完整語意。

**校準方式**：POC 範圍外，屬推理層工程（Agent 工具箱建設階段）。

## §5 與元原則的收斂性

自上而下推導（元原則）的結論：
> ETL 層只標記信號的存在，不詮釋信號的意義。

自下而上推導（五種語意類型）的結論：
> 可結構化的語意面向（概念共現）交給圖通道；不可結構化但可嵌入的語意面向交給向量通道；跨時間的認識論變遷交給時序通道。元對話合法丟棄。

兩條路徑收斂於同一架構，因為：

- **圖通道**存放的是共現頻率——脈絡無關的結構性事實 ✓
- **向量通道**不做任何存儲層判斷——它保存嵌入，語意在查詢時湧現 ✓
- **時序通道**的三值維度標記是最低限度的信號標記（真/假/不確定） ✓
- **所有語意詮釋**（關係方向性、推理鏈重建、動機理解）**均推遲至查詢時 LLM 處理** ✓

三通道的設計不是偶然的功能劃分，而是元原則的必然推論：在「脈絡無關的結構性事實」這個合法邊界內，恰好能容納共現拓撲（圖）、語意嵌入（向量）、認識論信號標記（事件）這三種且僅三種操作。
